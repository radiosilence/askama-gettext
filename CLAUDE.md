# askama_gettext

gettext for Askama templates, published to crates.io as `askama_gettext`.
[blit](https://github.com/radiosilence/blit) depends on it.

## Git

- Work in PRs; never push to main. PRs are squashed; merge main into a branch rather than rebasing.
- Never push tags or run `cargo publish`. CI tags and publishes when a release PR merges.
- Commits are signed.

## API

This is a library other people depend on. A change to anything `pub` is a semver
question: breaking changes wait for a minor release while the version is 0.x, and the
release PR's `Semver` job fails a bump that does not allow for them. Public structs
whose fields may grow are `#[non_exhaustive]`. `rust-version` in Cargo.toml is a
promise CI holds the crate to; raising it is a minor release.

## Changelog

`CHANGELOG.md` is generated by `scripts/changelog.py` and never edited by hand. Every change adds one fragment under `changelog.d/unreleased/<section>/`, named `<pr>-<slug>.md` and holding one `- **Lead.** Detail.` entry; to correct a note, edit its fragment. `just changelog --stdout` previews the result. The format is in `changelog.d/README.md`.

## Releasing

`just release patch|minor|major` (or an exact `X.Y.Z`) branches from main, bumps `Cargo.toml`, `Cargo.lock` and the README's dependency line, turns the unreleased fragments into the version and opens the release PR; `gh workflow run release.yml` does the same from CI. Merging it is the release: CI publishes the crate through crates.io trusted publishing, then the GitHub release with the changelog section as notes. A push releases only when it changes the version; `gh workflow run ci-cd.yml` on main retries a release that failed part way.

## CI

`.github/workflows/ci-cd.yml` is one workflow: CI jobs gated on the domains a change touches (worked out by its `changes` job), the `Checks` job the ruleset requires, then the release jobs on main. A skipped job is a domain the change did not touch and passes `Checks`. A new directory of code, or a new job, needs adding to `changes` and to `Checks`'s `needs`.
